# Gate 10 · Ed25519 signed witness attestations

**Temporal diode:** PAST observes → PRESENT deserves → FUTURE reserves.  
**Three independent lanes:** A / B / C · No vote · No quorum · No forced agreement.  
**Archive:** append only; signed sidecar events never overwrite the original temporal/delivery events.

## Signed boundary

The canonical sidecar ledger is [witness-attestations.jsonl](witness-attestations.jsonl). It starts empty until an actual witness signs an existing event. Each ATTEST entry refers to exactly one already-committed TEMPORAL or DELIVERY event by (stream, sequence, full SHA-256), one witness lane, and one registered Ed25519 verification key. A signature uses this exact **canonical sorted-key UTF-8 JSON** payload:

```json
{
  "domain": "ROOT0-ATTESTATION-v1",
  "witness": "A",
  "source_stream": "TEMPORAL",
  "source_seq": 1,
  "source_hash": "<SHA-256 of the exact referenced Git event>",
  "key_id": "<SHA-256 of raw 32-byte public Ed25519 key>"
}
```

The actual signed bytes have sorted keys and compact separators (generated by the `prepare` CLI); never retype the JSON. Signatures are exactly 64 raw Ed25519 bytes encoded as standard base64. The verifier checks domain separation, witness-to-key enrollment, witness-to-source ownership, unchanged source event hash, exact Ed25519 verification, signing payload checksum, and a second append-only attestation SHA chain. Nothing is inferred from silence or a majority.

## Enrollment is explicit — no generated real-world signatures

Initially, [witness-public-keys.json](witness-public-keys.json) has zero keys. Although Gate 09's actor registry binds A to GitHub account ID **148925959**, this is NOT equivalent to enrolling a cryptographic key. B and C remain unassigned in Gate 09, so they cannot enroll signing keys until distinct GitHub accounts have been independently reviewed. A GitHub account identity is not a proof of personhood.

Generate an A key **locally, offline, on the witness-owned machine** (install the pinned dependency locally with `python -m pip install cryptography==50.0.2`):

```sh
python bin/witness_keytool.py generate --witness A \
  --github-actor-id 148925959 \
  --private-out ~/.root0-witness-a-ed25519.pem
```

The tool writes the private PEM to the selected machine with an exclusive-create rule (mode 0600 on POSIX). Do not add this PEM to Git, paste it into ChatGPT, upload it to Pages, or store it in GitHub Actions Secrets unless a separately reviewed policy authorizes that. Securely back up the private key out of band. On Windows, enforce appropriate ACLs yourself.

Commit **only the printed public entry** by appending it to `keys` in the public key registry, following Git branch review. Never rewrite an older key entry. The registry enforces unique key IDs and the binding to the existing authenticated GitHub account.

## Walk a signed observation

1. Independently append a real witness record using [Gate 08](https://davidwise01.github.io/persist-cortex/temporal/). If the source is a remote offer or receipt, first append it through [Gate 09](https://davidwise01.github.io/persist-cortex/identity-bridge/).
2. After the public key is registered, run **locally**:

```sh
python bin/witness_attestation.py prepare \
  --witness A --source-stream TEMPORAL --source-seq 1 \
  --key-id YOUR_ENROLLED_64_HEX_PUBLIC_KEY_ID
```

3. Copy the `payload_b64` string from PREPARE and sign **locally**:

```sh
python bin/witness_keytool.py sign \
  --private-file ~/.root0-witness-a-ed25519.pem \
  --payload-b64 THE_EXACT_PREPARE_PAYLOAD_B64
```

4. The offline tool prints a detached `signature_b64`. Use the [authenticated Gate 10 append workflow](https://github.com/DavidWise01/toph-cortex/actions/workflows/witness-attestation-append.yml) with witness A, stream, source sequence, registered key ID, signature and the exact source/attestation tips from PREPARE. An actor-bound GitHub Action verifies everything, appends a single event and attempts a non-force Git push.
5. Open [Gate 10 reader](https://davidwise01.github.io/persist-cortex/signed-witness/) to replay the signed chain in the browser using WebCrypto Ed25519, if supported. A browser without Ed25519 must report unsupported/halting, not verified.

```sh
python bin/corpus_spine.py verify
python bin/temporal_diode.py verify
python bin/delivery_receipt.py verify
python bin/witness_attestation.py verify
python -m unittest discover -s tests -p 'test_gate10.py' -v
```

## Scope and limits

Ed25519 provides cryptographic evidence that someone possessing the signing private key signed the specific bytes. It does **not** independently prove the source statement true, confirm the human identity of the signer, prove distinct people control A/B/C, guarantee off-platform availability, or trigger execution. GitHub Actions authenticates the GitHub account initiating the append as an **additional** check; signatures are independent from GitHub's login system.

The verification key registry is public and governed by Git review; compromise of repository write permissions could alter unprotected branches. Protected branches, independent signed checkpoints and key-revocation handling are future boundaries. Existing legacy corpus-spine SHA mismatches remain marked invalid; new signed events must anchor to the verified v2 corpus chain. No private corpus contents or secret keys belong on GitHub Pages.

**No live witness public keys, signatures, or quorum have been fabricated or installed.**
